# 车队管理项目架构分析报告

## 一、项目概述

本项目是一个基于 **Taro + React + TypeScript + Supabase** 技术栈的多端车队管理系统，支持 H5、小程序和 Android 平台。

### 核心架构模式
```
页面 (Pages) → Hooks → db/api → Supabase
```

### 4.2 司机首页初始化流程

```typescript
// 1. 页面组件挂载
DriverHome: React.FC = () => {
  const { user } = useAuth({ guard: true })  // 认证守卫
  
  // 2. 初始化 Hooks
  const { warehouses, refresh: refreshWarehouses } = useDriverWarehouses(user?.id)
  const { data: stats, refresh: refreshStats } = useDriverDashboard({ userId: user?.id })
  
  // 3. 初始加载
  useEffect(() => {
    if (user?.id) {
      Promise.all([
        loadProfile(),      // → UsersAPI.getCurrentUserProfile()
        checkAttendance()   // → checkTodayAttendance(user.id)
      ])
    }
  }, [user?.id])
  
  // 4. Realtime 订阅
  useRealtimeSubscription({
    table: 'warehouse_assignments',
    filter: `user_id=eq.${user.id}`,
    onDataChange: () => {
      refreshWarehouses()
      refreshStats()
    }
  })
}
```

## 五、关键技术特性

### 5.1 缓存策略
- **Repository 层缓存**: 5分钟 TTL，减少重复查询
- **缓存失效**: 数据变更时通过 `eventBus` 发布事件，触发缓存清除
- **缓存键管理**: 使用 `CACHE_KEYS` 常量统一管理

### 5.2 实时订阅
- **Supabase Realtime**: 订阅 `warehouse_assignments` 等表的变更
- **降级策略**: WebSocket 失败时降级到轮询 (`usePollingNotifications`)
- **事件驱动刷新**: 收到变更事件后自动刷新相关数据

### 5.3 权限控制
- **角色枚举**: `DRIVER`, `MANAGER`, `BOSS`, `PEER_ADMIN`
- **权限推断**: 基于 `role` 和 `manager_permissions_enabled` 字段
- **RLS 策略**: 数据库层面的行级安全策略

### 5.4 事件总线
- **发布/订阅模式**: 使用 `eventBus` 实现组件间通信
- **事件类型**: `user:updated`, `vehicle:created`, `notification:read` 等
- **解耦设计**: API 层发布事件，UI 层订阅响应

## 六、总结

### 6.1 架构优势
1. **清晰的分层**: 页面 → Hooks → API → Repository → Supabase
2. **模块化设计**: 按功能域划分 API 模块，职责单一
3. **缓存优化**: Repository 层统一缓存管理，减少网络请求
4. **实时能力**: Supabase Realtime 支持数据实时同步
5. **类型安全**: TypeScript 全覆盖，类型定义完整

### 6.2 共用模块识别
- **高度共用**: `users.ts`, `notifications.ts`, `warehouses.ts`, `stats.ts`
- **中度共用**: `attendance.ts`, `leave.ts`, `piecework.ts`
- **特定角色**: `vehicles.ts` (Driver/Boss), `peer-admin.ts` (Boss)

### 6.3 数据流特点
- **批量并行查询**: 使用 `Promise.all` 优化初始加载
- **增量更新**: Realtime 订阅实现增量数据同步
- **缓存优先**: Repository 层优先返回缓存数据
