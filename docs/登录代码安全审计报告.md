## 二、安全漏洞

### 2.1 【高风险】密码明文存储在本地

**位置**: `src/pages/login/index.tsx` 第 256-258 行  
**置信度**: 高  

**推理过程**:
1. 用户勾选"记住账号密码"时，代码执行 `setStorageSync('saved_password', password)`
2. 密码以明文形式存储在 localStorage (H5) 或 Taro Storage (小程序)
3. 攻击者可通过 XSS 攻击、设备物理访问、或恶意浏览器扩展读取明文密码

**代码证据**:
```typescript
if (rememberMe) {
  setStorageSync('saved_account', account)
  setStorageSync('saved_password', password)  // ⚠️ 明文存储
  setStorageSync('remember_me', true)
}
```

**修复建议**:
1. **方案A（推荐）**: 移除"记住密码"功能，仅保留"记住账号"
2. **方案B**: 使用加密存储，但密钥管理是难点
3. **方案C**: 使用 Supabase 的 refresh token 机制实现自动登录，而非存储密码

---

### 2.2 【中风险】登录错误信息泄露

**位置**: `src/pages/login/index.tsx` 第 243-247 行  
**置信度**: 中  

**推理过程**:
1. 登录失败时，代码区分了"账号或密码错误"和其他错误
2. 虽然已做了一定处理，但 `error.message` 可能泄露后端实现细节
3. 攻击者可通过错误信息推断账号是否存在

**代码证据**:
```typescript
if (error.message.includes('Invalid login credentials')) {
  showToast({title: '账号或密码错误', icon: 'none', duration: 2000})
} else {
  showToast({title: error.message || '登录失败', icon: 'none', duration: 2000})
  // ⚠️ 直接显示后端错误信息
}
```

**修复建议**:
```typescript
// 统一错误提示，不泄露具体原因
showToast({title: '登录失败，请检查账号密码', icon: 'none', duration: 2000})
// 仅在开发环境记录详细错误
if (process.env.NODE_ENV === 'development') {
  console.error('[登录失败]', error)
}
```

### 2.3 【低风险】缺少登录频率限制（客户端）

**位置**: `src/pages/login/index.tsx` 全局  
**置信度**: 中  

**推理过程**:
1. 密码登录没有客户端频率限制
2. 虽然 Supabase 后端有限制，但客户端无限制会增加后端压力
3. 验证码发送有 60 秒倒计时限制（已实现）

**修复建议**:
```typescript
// 添加登录失败计数和锁定机制
const [loginAttempts, setLoginAttempts] = useState(0)
const [lockUntil, setLockUntil] = useState<number | null>(null)

// 登录失败时
if (error) {
  setLoginAttempts(prev => prev + 1)
  if (loginAttempts >= 5) {
    setLockUntil(Date.now() + 5 * 60 * 1000) // 锁定5分钟
  }
}
```

**待确认**: Supabase 后端是否已配置足够的频率限制

## 三、可优化点

### 3.1 【中优先级】动态导入 Supabase 客户端

**位置**: 多处 `await import('@/client/supabase')`  
**置信度**: 高  

**推理过程**:
1. 代码中多次使用 `await import('@/client/supabase')` 动态导入
2. 每次调用都会执行模块解析，虽然 JS 引擎会缓存，但增加了代码复杂度
3. 登录页面必然需要 Supabase，可以直接静态导入

**代码证据**:
```typescript
// 第 75 行 (clearOldAuthTokens)
const {supabase} = await import('@/client/supabase')
// 第 165 行 (handleSendOtp)
const {supabase} = await import('@/client/supabase')
// 第 199 行 (handleOtpLogin)
const {supabase} = await import('@/client/supabase')
// 第 237 行 (handlePasswordLogin)
const {supabase} = await import('@/client/supabase')
```

**修复建议**:
```typescript
// 在文件顶部直接导入
import { supabase } from '@/client/supabase'
```

---

### 3.2 【低优先级】会话创建失败时的处理不一致

**位置**: `handleOtpLogin` 和 `handlePasswordLogin` 中的 else 分支  
**置信度**: 高  

**推理过程**:
1. 当无法获取 userId 时，代码仍然允许跳转到首页
2. 这会导致单点登录功能失效
3. 两处代码逻辑重复

**代码证据**:
```typescript
// handleOtpLogin 第 209-218 行
if (userId) {
  await handleLoginSuccess(userId)
} else {
  console.warn('[OTP登录] 无法获取用户ID，跳过会话创建')
  // 重复的跳转逻辑...
}

// handlePasswordLogin 第 272-281 行 - 相同的重复代码
```

**修复建议**:
```typescript
// 统一处理，如果无法获取 userId 应该视为登录失败
if (!userId) {
  showToast({title: '登录异常，请重试', icon: 'none'})
  return
}
await handleLoginSuccess(userId)
```

const loginEmail = account.includes('@') ? account : `${account}@test.local`
