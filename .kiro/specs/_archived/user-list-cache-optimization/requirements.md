# 用户列表缓存优化 - 需求文档

## 简介

优化老板端和车队长端的用户列表加载性能，通过增强缓存策略和实时更新机制，减少不必要的数据库查询，提升用户体验。

## 术语表

- **用户列表 (User List)**: 老板端的用户管理页面和车队长端的司机管理页面显示的用户数据
- **缓存 (Cache)**: 存储在本地的数据副本，用于减少网络请求
- **实时更新 (Realtime Update)**: 当数据库数据变化时，自动更新本地缓存和界面
- **Supabase Realtime**: Supabase 提供的实时数据订阅功能
- **版本化缓存 (Versioned Cache)**: 带有版本号的缓存机制，支持缓存失效管理

## 需求

### 需求 1：增强缓存策略

**用户故事**: 作为老板或车队长，我希望用户列表能快速加载，而不是每次都要等待数据从服务器加载。

#### 验收标准

1. WHEN 用户首次进入用户管理页面 THEN 系统应从数据库加载用户列表并缓存到本地
2. WHEN 用户再次进入用户管理页面且缓存未过期 THEN 系统应立即从缓存加载用户列表，无需等待网络请求
3. WHEN 缓存数据存在 THEN 页面应在 100ms 内显示用户列表
4. WHEN 用户下拉刷新 THEN 系统应强制从数据库重新加载并更新缓存
5. WHEN 缓存过期时间到达 THEN 系统应在后台自动刷新缓存，不影响当前显示

### 需求 2：延长缓存有效期

**用户故事**: 作为老板或车队长，我希望用户列表的缓存时间更长，因为用户信息不会频繁变动。

#### 验收标准

1. WHEN 系统缓存用户列表数据 THEN 缓存有效期应设置为 30 分钟（从当前的 5 分钟延长）
2. WHEN 用户信息发生变更（添加、删除、修改） THEN 系统应立即清除相关缓存并触发重新加载
3. WHEN 仓库分配发生变更 THEN 系统应立即清除相关缓存并触发重新加载
4. WHEN 用户类型切换（纯司机/带车司机） THEN 系统应立即清除相关缓存并触发重新加载
5. WHEN 缓存即将过期（剩余 5 分钟） THEN 系统应在后台预加载新数据
6. WHEN 用户手动刷新 THEN 系统应清除缓存并从数据库重新加载，然后重置缓存有效期为 30 分钟
7. WHEN 应用重启 THEN 系统应保留缓存数据（使用持久化存储）

### 需求 3：实时更新机制

**用户故事**: 作为老板或车队长，当有用户信息变更时，我希望能自动看到最新数据，而不需要手动刷新。

#### 验收标准

1. WHEN 有新用户被添加 THEN 系统应立即清除缓存并从数据库重新加载用户列表
2. WHEN 用户信息被修改（姓名、角色、仓库分配等） THEN 系统应立即清除缓存并从数据库重新加载用户列表
3. WHEN 用户被删除或停用 THEN 系统应立即清除缓存并从数据库重新加载用户列表
4. WHEN 数据库数据变更 THEN 系统应通过 Supabase Realtime 监听变更事件并触发缓存重新加载
5. WHEN 实时更新失败 THEN 系统应降级到轮询模式（每 30 秒检查一次数据版本）
6. WHEN 用户离开页面 THEN 系统应取消实时订阅以节省资源
7. WHEN 缓存重新加载完成 THEN 系统应自动刷新界面显示最新数据

### 需求 4：缓存失效和重新加载机制

**用户故事**: 作为系统，当数据发生变更时，我需要确保缓存立即失效并重新加载最新数据。

#### 验收标准

1. WHEN 执行添加用户操作成功 THEN 系统应立即调用缓存失效函数并触发重新加载
2. WHEN 执行修改用户操作成功 THEN 系统应立即调用缓存失效函数并触发重新加载
3. WHEN 执行删除用户操作成功 THEN 系统应立即调用缓存失效函数并触发重新加载
4. WHEN 执行仓库分配操作成功 THEN 系统应立即调用缓存失效函数并触发重新加载
5. WHEN 执行用户类型切换操作成功 THEN 系统应立即调用缓存失效函数并触发重新加载
6. WHEN 缓存失效函数被调用 THEN 系统应清除所有相关缓存键（用户列表、用户详情、仓库分配）
7. WHEN 缓存清除完成 THEN 系统应立即从数据库重新加载数据并更新界面
8. WHEN 重新加载失败 THEN 系统应显示错误提示并提供重试按钮

### 需求 5：分层加载策略

**用户故事**: 作为老板或车队长，我希望能快速看到用户的基本信息，详细信息可以按需加载。

#### 验收标准

1. WHEN 用户进入用户管理页面 THEN 系统应优先加载用户的基本信息（姓名、手机号、角色）
2. WHEN 用户展开某个用户的详情 THEN 系统应按需加载该用户的详细信息（驾驶证、车辆、仓库分配）
3. WHEN 用户详细信息已加载 THEN 系统应缓存该详细信息，避免重复加载
4. WHEN 用户收起详情 THEN 系统应保留已加载的详细信息缓存
5. WHEN 用户信息变更 THEN 系统应只更新变更的部分，不重新加载所有数据

### 需求 6：智能预加载

**用户故事**: 作为老板或车队长，我希望系统能智能预测我可能需要的数据并提前加载。

#### 验收标准

1. WHEN 用户滚动到列表底部附近 THEN 系统应预加载下一批用户的详细信息
2. WHEN 用户在某个用户卡片上停留超过 1 秒 THEN 系统应预加载该用户的详细信息
3. WHEN 用户切换标签页（司机/管理员） THEN 系统应预加载目标标签页的用户数据
4. WHEN 用户切换仓库 THEN 系统应预加载该仓库的用户数据
5. WHEN 预加载失败 THEN 系统应静默失败，不影响用户操作

### 需求 7：缓存管理和清理

**用户故事**: 作为系统，我需要合理管理缓存，避免占用过多存储空间。

#### 验收标准

1. WHEN 缓存数据总大小超过 10MB THEN 系统应清理最旧的缓存数据
2. WHEN 用户退出登录 THEN 系统应清除所有用户相关的缓存
3. WHEN 应用版本更新 THEN 系统应清除旧版本的缓存数据
4. WHEN 缓存数据损坏 THEN 系统应自动清除并重新加载
5. WHEN 用户手动清除缓存 THEN 系统应提供清除缓存的功能入口

### 需求 8：性能指标

**用户故事**: 作为开发者，我需要确保优化后的性能达到预期目标。

#### 验收标准

1. WHEN 从缓存加载用户列表 THEN 加载时间应小于 100ms
2. WHEN 从数据库首次加载用户列表 THEN 加载时间应小于 2 秒（50 个用户）
3. WHEN 实时更新触发 THEN 界面更新延迟应小于 500ms
4. WHEN 用户展开详情 THEN 详细信息加载时间应小于 1 秒
5. WHEN 缓存命中率 THEN 应达到 80% 以上（在正常使用场景下）

### 需求 9：错误处理和降级

**用户故事**: 作为用户，即使在网络不稳定的情况下，我也希望能看到缓存的数据。

#### 验收标准

1. WHEN 网络请求失败且有缓存数据 THEN 系统应显示缓存数据并提示"显示的是离线数据"
2. WHEN 网络请求失败且无缓存数据 THEN 系统应显示友好的错误提示和重试按钮
3. WHEN 实时更新连接失败 THEN 系统应自动降级到轮询模式
4. WHEN 缓存读取失败 THEN 系统应直接从数据库加载数据
5. WHEN 缓存写入失败 THEN 系统应记录错误但不影响数据显示

## 非功能需求

### 性能要求
- 缓存加载时间 < 100ms
- 首次加载时间 < 2s（50 个用户）
- 实时更新延迟 < 500ms
- 缓存命中率 > 80%

### 兼容性要求
- 支持 H5、微信小程序、Android APP
- 支持 localStorage（H5）和 Taro.storage（小程序/APP）

### 可维护性要求
- 缓存逻辑应封装为独立的 Hook
- 支持缓存版本管理
- 提供缓存调试工具

## 约束条件

1. 必须保持与现有代码的兼容性
2. 不能影响现有的权限控制逻辑
3. 必须支持多端（H5、小程序、APP）
4. 缓存数据必须加密存储（敏感信息）
5. 必须遵守 Supabase 的 API 调用限制
