# 计件报表页面缓存迁移 Spec

## 概述

本 Spec 定义了将计件报表页面（老板端和车队长端）从旧缓存系统迁移到新的统一缓存系统（`useUserListCache`）的完整方案。

## 背景

在"用户列表缓存优化"项目中，我们创建了新的统一缓存系统 `useUserListCache`，并已成功迁移了多个页面。但计件报表页面（2个）仍在使用旧的缓存函数（`getVersionedCache`, `setVersionedCache`, `clearVersionedCache`），需要迁移以提高性能和可维护性。

## 目标

1. ✅ 将老板端计件报表页面迁移到新缓存系统
2. ✅ 将车队长端计件报表页面迁移到新缓存系统
3. ✅ 移除所有旧缓存函数调用
4. ✅ 保持页面功能和用户体验不变
5. ✅ 确保代码质量符合项目规范
6. ✅ 验证迁移的正确性和性能

## 核心设计

### 架构变更

**迁移前**：
```
计件报表页面 → 旧缓存函数 → Supabase
```

**迁移后**：
```
计件报表页面 → useUserListCache Hook → useDataCache Hook → Supabase
                                      ↓
                                  实时监听器
```

### 关键组件

1. **useUserListCache Hook**
   - 提供用户列表、详情、仓库映射
   - 自动实时更新
   - 30 分钟缓存 TTL

2. **计件报表页面**
   - 使用 Hook 获取用户数据
   - 保持计件记录的独立加载
   - 添加权限过滤（车队长端）

### 正确性属性

1. **缓存数据一致性** - 缓存数据与 API 数据一致
2. **实时更新响应性** - 数据变更后 < 5秒自动更新
3. **资源清理完整性** - 页面卸载时正确清理资源
4. **功能等价性** - 迁移前后功能完全一致
5. **代码质量合规性** - 代码符合项目规范
6. **旧代码移除完整性** - 无残留旧缓存调用

### 技术要点

1. **仓库数据**：`useUserListCache` 只提供用户-仓库映射，完整仓库列表需单独加载
2. **计件记录**：计件记录数据量大且变化频繁，保持现有的独立加载逻辑
3. **权限过滤**：车队长端必须根据 `userWarehouseIdsMap` 过滤数据
4. **实时更新**：用户数据自动更新，计件记录需手动刷新
