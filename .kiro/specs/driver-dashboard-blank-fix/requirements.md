# 需求文档 - 司机工作台空白页修复

## 简介

司机账号登录成功后，司机工作台页面显示空白。根据代码分析，页面包含大量调试日志，且在数据加载失败时缺乏适当的错误处理和用户反馈。本需求旨在诊断根本原因，修复数据加载问题，改善错误处理，并清理调试代码。

## 术语表

- **司机工作台 (Driver_Dashboard)**: 司机登录后的首页，显示打卡状态、计件统计、仓库信息等
- **仓库 (Warehouse)**: 司机工作的地点，每个司机可以分配到一个或多个仓库
- **API_请求 (API_Request)**: 前端向后端发起的数据请求
- **错误处理 (Error_Handling)**: 当操作失败时的处理逻辑
- **加载状态 (Loading_State)**: 数据加载过程中的 UI 状态
- **空状态 (Empty_State)**: 当没有数据时显示的 UI 状态

## 需求

### 需求 1: 诊断空白页根本原因

**用户故事**: 作为开发者，我想要诊断司机工作台空白页的根本原因，以便能够针对性地修复问题。

#### 验收标准

1. WHEN 司机登录并进入工作台 THEN 系统 SHALL 记录所有 API 请求的状态（成功/失败）
2. WHEN API 请求失败 THEN 系统 SHALL 记录详细的错误信息（状态码、错误消息、请求参数）
3. WHEN 页面组件加载失败 THEN 系统 SHALL 记录组件加载错误
4. WHEN 数据为空 THEN 系统 SHALL 区分"加载失败"和"数据为空"两种情况
5. THE 系统 SHALL 提供诊断工具或日志来帮助定位问题

### 需求 2: 改善 API 错误处理

**用户故事**: 作为司机，当数据加载失败时，我想要看到清晰的错误提示，以便知道发生了什么问题。

#### 验收标准

1. WHEN 仓库列表 API 请求失败 THEN 系统 SHALL 显示友好的错误提示
2. WHEN 打卡状态 API 请求失败 THEN 系统 SHALL 显示默认的未打卡状态
3. WHEN 统计数据 API 请求失败 THEN 系统 SHALL 显示零值统计
4. WHEN 网络连接失败 THEN 系统 SHALL 提示用户检查网络连接
5. WHEN 认证失败（401 错误）THEN 系统 SHALL 提示用户重新登录

### 需求 3: 优化加载状态显示

**用户故事**: 作为司机，在数据加载过程中，我想要看到加载指示器，以便知道系统正在工作。

#### 验收标准

1. WHEN 页面开始加载数据 THEN 系统 SHALL 显示全局加载指示器
2. WHEN 单个数据块加载中 THEN 系统 SHALL 显示该数据块的加载状态
3. WHEN 所有数据加载完成 THEN 系统 SHALL 隐藏加载指示器
4. WHEN 数据加载超过 5 秒 THEN 系统 SHALL 显示"加载时间较长"的提示
5. THE 加载指示器 SHALL 不阻止用户查看已加载的内容

### 需求 4: 实现空状态处理

**用户故事**: 作为司机，当我没有分配仓库或没有数据时，我想要看到清晰的说明，以便知道如何操作。

#### 验收标准

1. WHEN 司机未分配仓库 THEN 系统 SHALL 显示"暂未分配仓库"的空状态提示
2. WHEN 司机没有打卡记录 THEN 系统 SHALL 显示"今日未打卡"的提示和打卡按钮
3. WHEN 司机没有计件记录 THEN 系统 SHALL 显示零值统计
4. WHEN 显示空状态 THEN 系统 SHALL 提供操作建议（如"请联系管理员"）
5. THE 空状态提示 SHALL 使用友好的图标和文案

### 需求 5: 清理调试代码

**用户故事**: 作为开发者，我想要清理生产代码中的调试日志，以便提高代码质量和性能。

#### 验收标准

1. THE 系统 SHALL 移除所有 console.log 调试语句
2. THE 系统 SHALL 移除页面顶部的调试信息显示
3. THE 系统 SHALL 使用统一的日志工具（logger）替代 console.log
4. WHEN 需要调试时 THEN 开发者 SHALL 通过日志工具查看日志
5. THE 生产环境 SHALL 禁用详细日志输出

### 需求 6: 添加重试机制

**用户故事**: 作为司机，当数据加载失败时，我想要能够重试，以便在临时网络问题后恢复正常。

#### 验收标准

1. WHEN API 请求失败 THEN 系统 SHALL 显示"重试"按钮
2. WHEN 用户点击重试按钮 THEN 系统 SHALL 重新发起失败的请求
3. WHEN 重试成功 THEN 系统 SHALL 更新页面数据
4. WHEN 重试失败 THEN 系统 SHALL 再次显示错误提示和重试按钮
5. THE 系统 SHALL 限制自动重试次数（最多 3 次）

### 需求 7: 改善页面渲染逻辑

**用户故事**: 作为司机，即使部分数据加载失败，我也想要看到已成功加载的数据，以便能够使用部分功能。

#### 验收标准

1. WHEN 仓库数据加载失败 THEN 系统 SHALL 仍然显示打卡状态和统计数据
2. WHEN 打卡数据加载失败 THEN 系统 SHALL 仍然显示仓库列表和统计数据
3. WHEN 统计数据加载失败 THEN 系统 SHALL 仍然显示仓库列表和打卡状态
4. THE 系统 SHALL 使用独立的错误状态管理每个数据块
5. THE 页面 SHALL 采用渐进式渲染，不因单个数据块失败而完全空白

### 需求 8: 添加错误边界

**用户故事**: 作为开发者，我想要捕获组件渲染错误，以便防止整个页面崩溃。

#### 验收标准

1. WHEN 组件渲染过程中发生错误 THEN 系统 SHALL 捕获错误并记录
2. WHEN 组件渲染错误 THEN 系统 SHALL 显示降级 UI（如错误提示）
3. WHEN 子组件错误 THEN 系统 SHALL 不影响其他组件的正常显示
4. THE 系统 SHALL 提供错误恢复机制（如重新加载组件）
5. THE 错误信息 SHALL 包含足够的上下文用于调试

## 优先级

1. 需求 1（诊断）- 最高优先级
2. 需求 2（错误处理）- 高优先级
3. 需求 3（加载状态）- 高优先级
4. 需求 4（空状态）- 中优先级
5. 需求 7（渲染逻辑）- 中优先级
6. 需求 5（清理调试）- 中优先级
7. 需求 6（重试机制）- 低优先级
8. 需求 8（错误边界）- 低优先级
