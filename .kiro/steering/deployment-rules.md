# 部署与测试规则

> **核心原则**：默认进行本地测试，只有在用户明确要求时才进行部署。

## 🚨 强制规则：本地测试优先

### 默认行为

当用户要求测试、调试或验证功能时，**默认执行本地测试流程**：

1. **启动后端**：在 `fleet-manager/backend` 目录启动 FastAPI
2. **构建前端 H5**：`npm run build:h5`
3. **启动本地服务器**：`npx serve dist/build/h5 -l 8080 -s`
4. **在浏览器中测试**：访问 `http://localhost:8080`

### 触发条件

| 用户请求 | 执行操作 |
|---------|---------|
| "测试"、"调试"、"验证" | 本地测试（默认） |
| "部署到线上"、"发布" | Docker 部署 |

## 本地测试流程

### 步骤 1：启动后端（在 fleet-manager/backend 目录）
```bash
# Windows
venv\Scripts\activate
python main.py

# Linux/Mac
source venv/bin/activate
python main.py
```

后端 API 文档：http://localhost:8000/docs

### 步骤 2：构建前端 H5（在 fleet-manager/frontend 目录）
```bash
npm run build:h5
```

### 步骤 3：启动本地服务器
```bash
npx serve dist/build/h5 -l 8080 -s
```

### 步骤 4：测试验证
- 浏览器访问：`http://localhost:8080`
- 后端 API：`http://localhost:8000`
- API 文档：`http://localhost:8000/docs`

## Docker 部署流程

**仅在用户明确要求时执行**，关键词：
- "部署到线上"
- "发布到生产"
- "Docker 部署"

### 执行步骤（在 fleet-manager 目录）
```bash
# 配置环境变量
cp .env.template .env
# 编辑 .env 设置必要配置

# 启动所有服务
docker-compose up -d

# 生产环境
docker-compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

### 服务地址
- 前端：http://localhost
- 后端 API：http://localhost:8000
- API 文档：http://localhost:8000/docs
- 数据库：localhost:5432

## 注意事项

### 不要自动执行的操作
- ❌ 不要在用户未明确要求时执行部署
- ❌ 不要跳过本地测试直接部署

### 必须确认的情况
- 如果不确定用户意图，询问是要本地测试还是部署
- 如果本地测试发现问题，先修复再考虑部署

### 本地测试的优势
- 快速迭代，无需等待部署
- 可以使用浏览器开发者工具调试
- 不影响线上用户
- 节省部署时间和资源

## 🚨 本地测试自主准备规则（强制）

> **硬性规则**：本地测试必须自主准备好所有环境，不要询问用户！

### 强制要求

当用户要求"本地测试"时，**必须自主完成以下所有步骤**：

1. **检查并启动后端服务**（如果未运行）
2. **构建前端 H5**
3. **启动前端本地服务器**
4. **验证服务正常运行**

### 自主准备流程

```
用户请求"本地测试"
    │
    ▼
┌─────────────────────────────────────┐
│ 1. 检查后端服务是否运行              │

    │
    ▼
┌─────────────────────────────────────┐
│ 2. 构建前端 H5                       │
│    - npm run build:h5               │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│ 3. 启动前端本地服务器                │

└─────────────────────────────────────┘

    │
    ▼
通知用户测试环境已就绪
```

### fleet-manager 项目本地测试命令

#### 后端启动（在 fleet-manager/backend 目录）
```bash
# Windows
venv\Scripts\activate
python -m uvicorn main:app --host 0.0.0.0 --port 8000

# Linux/Mac
source venv/bin/activate
python -m uvicorn main:app --host 0.0.0.0 --port 8000
```

#### 前端构建和启动（在 fleet-manager/frontend 目录）
```bash
# 构建 H5
npm run build:h5

# 启动本地服务器
npx serve dist/build/h5 -l 8080 -s
```

### 禁止行为
- ❌ 不要询问用户"是否需要启动后端"
- ❌ 不要询问用户"是否需要构建前端"
- ❌ 不要只启动前端而忘记后端
- ❌ 不要在环境未就绪时就告诉用户"测试环境已就绪"

### 违规后果
- 测试环境不完整会导致功能无法正常测试
- 必须自主完成所有准备工作后再通知用户
