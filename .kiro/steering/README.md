# Kiro Steering 规则说明

这个目录包含了项目的编码规范、工作流程和上下文信息，用于指导 Kiro AI 助手更好地理解和协助开发。

> **快速开始**：请先阅读 `SUMMARY.md` 了解规则概览和强制要求！

## 文件说明

### `SUMMARY.md` 📋 **推荐首先阅读**
**规则总结** - 快速了解所有规则：
- 强制规则概览
- 规则文件结构
- 快速开始指南
- 提交前检查清单

**适用场景**：新成员入门、快速查阅

### `mandatory-rules.md` 🚨 **必读**
**强制规则** - 必须 100% 遵守的硬性规则：
- 规则 1：所有代码必须有完整注释
- 规则 2：文档必须实时同步更新
- 详细的执行要求和示例
- 违规后果说明

**适用场景**：始终生效（inclusion: always），所有开发活动必须遵守

### `workflow-guide.md` ⭐
**工作流选择指南** - 帮助你选择合适的工作流：
- Kiro Spec 工作流 vs 6A 工作流对比
- 何时使用哪个工作流
- 工作流切换指南
- 混合使用策略

**适用场景**：开始新任务前必读

### `project-workflow.md`
**6A 工作流规则** - 定义了完整的项目开发流程：
- Align (对齐阶段)：需求分析和规范化
- Architect (架构阶段)：系统设计和架构
- Atomize (原子化阶段)：任务拆分
- Approve (审批阶段)：人工审查
- Automate (自动化执行)：代码实现
- Assess (评估阶段)：质量评估

**适用场景**：复杂任务、重大重构（不是标准功能开发）

### `coding-standards.md`
**编码规范** - 定义了代码编写的标准：
- TypeScript/JavaScript 规范
- Vue 3 / UniApp 规范
- Python / FastAPI 规范
- 代码风格
- 测试要求
- 文档要求

**适用场景**：所有代码编写活动

### `project-context.md`
**项目上下文** - 提供项目的背景信息：
- 技术栈（UniApp + Vue3 + FastAPI）
- 项目结构
- 核心功能模块
- 重要约定
- 部署流程

**适用场景**：始终生效（inclusion: always）

### `deployment-rules.md` 🚀 **重要**
**部署与测试规则** - 定义测试和部署的默认行为：
- 默认进行本地测试
- 只有明确要求时才执行部署
- 本地测试流程和命令

**适用场景**：所有测试、调试、部署相关活动

## 如何使用

### 全局规则（始终生效）
这些规则会在所有对话中自动加载：
- `project-context.md`（已设置 `inclusion: always`）
- `coding-standards.md`
- `project-workflow.md`

### 条件规则（特定文件触发）
如果需要某些规则只在特定文件类型时生效，可以在文件开头添加：

```markdown
---
inclusion: fileMatch
fileMatchPattern: 'fleet-manager/frontend/**/*.vue'
---
```

### 手动规则（需要时引用）
如果需要某些规则只在手动引用时生效，可以在文件开头添加：

```markdown
---
inclusion: manual
---
```

然后在聊天中使用 `#` 引用该规则。

## 规则优先级

1. **强制规则** (`mandatory-rules.md`) - 🚨 必须 100% 遵守（最高优先级）
2. **部署规则** (`deployment-rules.md`) - 🚀 默认本地测试，明确要求才部署
3. **项目上下文** (`project-context.md`) - 提供基础信息
4. **工作流选择** (`workflow-guide.md`) - 选择合适的工作流
5. **编码规范** (`coding-standards.md`) - 定义代码标准
6. **工作流规则** (`project-workflow.md`) - 6A 工作流详细指南（仅在使用 6A 工作流时参考）

## ⚠️ 强制要求（必须遵守）

### 1. 所有代码必须有注释
- **所有函数都必须添加注释**（JSDoc/docstring）
- **所有文件开头必须添加文件说明**
- **所有复杂逻辑必须添加行内注释**
- **即使是简单函数也必须注释**
- 无例外！

### 2. 文档必须实时同步
- **代码变更时必须立即更新相关文档**
- **不允许先改代码后补文档**
- **文档与代码必须保持 100% 同步**
- **每次提交前必须确认文档已更新**
- 无例外！

## 快速开始

### 开始新任务时
1. 阅读 `workflow-guide.md` 选择合适的工作流
2. **大多数情况下使用 Kiro Spec 工作流**（`.kiro/specs/`）
3. 只有复杂任务或重构才使用 6A 工作流（`fleet-manager/docs/`）

### 编写代码时
1. 遵循 `coding-standards.md` 中的规范
2. 参考 `project-context.md` 了解项目约定
3. **所有代码必须添加完整注释**（强制）
4. 实现功能后立即编写测试
5. **立即更新相关文档**（强制）

## 更新规则

当需要更新规则时：
1. 直接编辑对应的 `.md` 文件
2. 确保格式正确（Markdown 格式）
3. 如果添加新规则文件，更新此 README

## 注意事项

- Steering 文件使用 Markdown 格式
- 支持 front-matter 配置（YAML 格式）
- 可以使用 `#[[file:相对路径]]` 引用其他文件
- 规则会在 Kiro 重启或重新加载时生效
