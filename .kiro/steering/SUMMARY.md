# Kiro Steering 规则总结

## 🚨 七大强制规则（必须 100% 遵守）

### 1. 所有代码必须有完整注释
- **所有函数**都必须添加 JSDoc 注释
- **所有文件**开头必须添加文件说明
- **所有复杂逻辑**必须添加行内注释
- **所有魔法数字**必须注释说明含义
- **即使是简单函数也必须注释**

### 2. 文档必须实时同步更新
- **代码变更时必须立即更新文档**
- **不允许先改代码后补文档**
- **文档与代码必须保持 100% 同步**
- **每次提交前必须确认文档已更新**

### 3. 所有对话输出必须使用中文
- **所有回复必须使用中文**
- **新对话必须继承上一个对话的上下文**
- **必须查看任务文档了解当前进度**
- **技术术语可保留英文，但需中文解释**

### 4. 默认本地测试，明确要求才部署 🚀
- **默认执行本地测试流程**（构建 H5 + 本地服务器）
- **只有用户明确说"热更新"/"部署"时才执行热更新**
- **只有用户明确说"构建APK"/"打包APK"时才构建 APK**
- **不要跳过本地测试直接部署**

### 5. 编码错误必须标记并修复 🔧
- **发现错误时必须立即标记**（文件、行号、错误内容）
- **当前任务完成后必须修复所有标记的错误**
- **不允许遗留未修复的编码错误**
- **修复后必须验证错误已解决**

### 6. 发现问题时必须全局检查 🔍
- **发现一个问题时必须检查其他地方是否有相同问题**
- **使用 grep 搜索整个项目中的相同代码模式**
- **一次性修复所有相同问题，不要只修复单个文件**
- **验证所有修复都已生效**

### 7. 进程管理必须规范 ⚙️
- **构建失败或超时时必须立即终止进程**
- **启动新进程前必须检查并清理旧进程**
- **不允许遗留僵尸进程**
- **避免多个相同进程同时运行**

### 8. 删除优化必须全面扫描和深度测试 🗑️
- **删除前必须使用 grep 搜索所有引用**
- **必须分析每个调用点的上下文和功能影响**
- **删除后必须验证 TypeScript 编译通过**
- **涉及页面功能时必须进行本地 H5 测试**
- **导致功能回归的删除必须立即回滚**

详细说明请查看：`mandatory-rules.md` 和 `deployment-rules.md`

## 🚀 快速开始

### 第一步：了解强制规则
阅读 `mandatory-rules.md`，理解两大强制规则：
- 所有代码必须有注释
- 文档必须实时同步

### 第二步：选择工作流
阅读 `workflow-guide.md`，选择合适的工作流：
- **标准功能开发** → Kiro Spec 工作流
- **复杂任务重构** → 6A 工作流
- **不确定时** → 默认 Kiro Spec

### 第三步：遵循编码规范
阅读 `coding-standards.md`，遵循项目编码规范：
- TypeScript 规范
- React/Taro 规范
- 测试要求
- 文档要求

### 第四步：开始开发
- 编写代码时添加完整注释
- 代码变更时立即更新文档
- 提交前检查文档同步清单

## 🎓 核心理念

### 质量优先
- 代码质量 = 代码逻辑 + 代码注释 + 文档同步
- 未注释的代码 = 未完成的代码
- 未同步的文档 = 未完成的工作

### 实时同步
- 代码和文档是一体的，不可分割
- 不允许"先写代码，后补文档"
- 不允许"代码完成了，文档还没更新"

### 可维护性
- 完整的注释让代码易于理解
- 同步的文档让项目易于维护
- 清晰的规范让团队协作更高效

## 💡 最佳实践

### 编写代码时
1. 先写函数签名和 JSDoc 注释
2. 再实现函数逻辑
3. 为复杂逻辑添加行内注释
4. 运行测试确保功能正常
5. 立即更新相关文档

### 修改代码时
1. 修改代码逻辑
2. 同步更新代码注释
3. 运行测试确保功能正常
4. 立即更新相关文档
5. 检查文档同步清单

### 提交代码时
1. 检查所有代码是否有注释
2. 检查所有文档是否已同步
3. 运行测试和 lint
4. 提交代码和文档
